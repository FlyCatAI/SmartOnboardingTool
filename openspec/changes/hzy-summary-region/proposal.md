## Why

慧展业（客户经理展业）「历史业绩」页当前只有明细列表，客户经理需要在多页之间手工合计才能掌握个人本年度与历史累计的收单业绩，回顾过程冗长、易错。GRA-31 已沉淀 PRD、GRA-32 已沉淀 42 条测试案例，业务方已闭环。本次变更在 rm-mvp-prd MVP 基线之上增量交付「年度业绩汇总区」，让客户经理打开历史业绩页即可看到本年度与历史累计两组核心指标，无需自行汇总。

## What Changes

- 新增 capability `performance`，对外开放一个查询接口：年度业绩汇总查询。
- 汇总区固定挂在「历史业绩」页顶部、历史业绩列表上方；明细列表本身的筛选 / 排序 / 翻页 / 详情入口保持不变。
- 汇总区由后端统一计算，前端只做格式化展示——不在前端基于分页列表自行求和。
- 汇总区与历史业绩列表的筛选条件互相独立：列表筛选条件变化不影响汇总区，汇总区仅按登录态与数据权限解析口径。
- 数据口径沿用现有慧展业达标 / 有效 / 收入归属规则，不在本次新增业务判定逻辑。
- 汇总接口返回数据统计截止时间，前端按 `YYYY-MM-DD HH:mm` 展示，覆盖 T+1 / 缓存 / 物化视图等可能存在数据延迟的实现形态。
- 性能目标：汇总接口 P95 ≤ 2 秒。
- 错误形态：汇总接口失败时汇总区独立降级，不阻塞下方历史业绩列表加载与操作。

## Capabilities

### New Capabilities

- `performance`: 客户经理 / 团队主管 / 支行行长视角的本年度 + 历史累计收单业绩汇总。提供单一只读接口与单一 UI 区域（历史业绩页顶部汇总区）；不含图表趋势、同比环比、目标达成率、团队排行等扩展能力（v1.1+ 范围）。

## Impact

- **业务影响**：联合收单业务一线客户经理在历史业绩页可直接看到本年度与历史累计两组核心指标（入网商户数、达标商户数、有效商户数、总收入），减少手工合计；团队主管 / 支行行长按现有数据权限范围查看。
- **接口影响**：新增 `GET /api/v1/performance/summary`，鉴权与数据权限沿用 rm-mvp-prd `auth-and-identity` / 现有数据范围模型。
- **数据影响**：建议沉淀汇总表或物化视图（按客户经理 + 年份 + 统计周期）以满足 P95 ≤ 2 秒目标；如直读实时聚合，需具备本年度索引覆盖。具体落地由开发团队评审决定。
- **依赖系统**：依赖现有商户主数据（入网 / 归属）与收单交易系统（收入），不新增下游对接系统。
- **数据合规**：汇总接口仅返回聚合指标，不返回单笔交易或敏感字段明文，无 OTP 调阅链路。
- **回滚预案**：前端汇总区独立加载失败不影响列表；如后端汇总接口下线，前端按"数据加载失败"占位展示，业务功能（历史业绩列表）继续可用。

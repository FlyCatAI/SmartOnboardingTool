# 行内 SSO 桥接调研笔记（任务 1.1 / 4.1 前置）

> 作用：为 PM 牵头的 SSO 接口对齐会议（任务 1.1）提供候选方案对比与问题清单。
> 范围：客户经理展业小程序 v1 的登录与会话续期；OTP 通道单独由任务 1.6 与安合团队对齐，本文不展开。
> 输入：design.md Decision 2 / auth-and-identity/spec.md / OQ 3.2、3.7。
> 输出：本文 + 对齐会议后落入《下游接口对齐纪要》并补 auth 模块实现。

## 1. 候选桥接路径

OQ 3.7「小程序入口归属」未定，候选 3 条路径在 SSO 桥接形态上差异显著。

### 路径 A：挂在行内员工 App 子菜单（WebView 起跳，复用员工 App 已建会话）

- 行内员工 App 已完成 SSO 登录；小程序作为 H5 / 小程序内嵌于员工 App 的子菜单
- 员工 App 通过 `wx.openEmbeddedMiniProgram` 或自家容器协议把当前会话凭证传给小程序
- 小程序首屏拿到凭证后向后端 `/auth/sso/exchange` 换取业务 session token

| 优点 | 缺点 |
|---|---|
| 用户无感知登录，体验最佳 | 凭证传递协议依赖员工 App 团队；容器升级有耦合 |
| 不需独立申请微信侧能力 | 出员工 App 即失效，独立分享链路受限 |
| 合规审查路径短 | OQ 3.7 若选 B/C，本路径作废 |

### 路径 B：行内统一小程序矩阵（同主体多小程序，跨小程序 union session）

- 行内有统一的「员工总入口」小程序，业务小程序通过 `union id` 或行内 `unionToken` 共享登录态
- 业务小程序首屏调用 `wx.login()` 拿 `code`，回传后端，后端再向行内 SSO 网关用 `unionToken` 换业务身份

| 优点 | 缺点 |
|---|---|
| 复用行内员工 unionToken 体系，跨业务一致 | 需小程序治理团队配合给 `appid` 授权 |
| 可独立展示在矩阵首页 | 首次启动仍需用户授权一次 |

### 路径 C：独立小程序 + 行内自有授权页 H5 桥接

- 业务小程序独立 appid 上架；首次启动 `wx.navigateToMiniProgram` 或 `web-view` 跳转行内自有授权页
- 用户输入工号/扫码完成 SSO，授权页回跳带 `code`，业务小程序后端用 `code` 换 token

| 优点 | 缺点 |
|---|---|
| 不依赖其它小程序 / App，归属清晰 | 用户体验最差（首登要离开小程序） |
| 治理简单（自己 appid 自己管） | 微信审核流程独立，发版节奏受微信影响 |

## 2. 与下游需要确认的 9 个问题（对齐会议清单）

1. **入口归属决策**：OQ 3.7 由谁、何时拍板？三条路径对工程影响差 1-2 周。
2. **凭证传递协议**：若选路径 A，员工 App 团队是否已暴露稳定的容器 API？协议版本与降级策略？
3. **`/auth/sso/exchange` 接口契约**：行内 SSO 网关是否已有对外接口？路径、入参（code / unionToken / 凭证）、出参字段、错误码、QPS 限流。
4. **会话有效期与续期策略**：spec 要求 8 小时有效期 + 自动续期，行内 SSO 是否原生支持？还是业务侧自管 refresh token？
5. **员工字段口径**：需要拿到 `employeeId / name / branchId / teamId / role`。SSO 是否返回组织信息？还是要走另一个 HR 接口补查？
6. **角色字段映射**：行内身份系统的「客户经理 / 主管」字段名是否一致？需补一份枚举映射表。
7. **测试环境**：行内 SSO 是否提供 sandbox？可用账号数量？
8. **首次登录后用户信息缓存**：用户员工号是否会在登录后变更（如调岗）？若变更，缓存策略与权限重算时机？
9. **下线 / 在职校验**：员工离职 / 调岗后会话是否立刻失效？业务侧检测频率？

## 3. 后端 SPI 与之对应

`com.flycat.rm.auth.SsoClient` 已留两个方法：
- `exchange(code)` —— 对应问题 3
- `refresh(sessionToken)` —— 对应问题 4

具体实现待答案到位后写入 `SsoClientImpl`（按选定路径选择 RestClient / WebClient）。

## 4. 与 spec 的对齐点

| spec Requirement | 待 SSO 答复后才能锁定 |
|---|---|
| 会话有效期 8 小时 / 自动续期 / 401 重新授权 | 问题 4 + 问题 9 |
| 用户身份字段（员工号 / 姓名 / 支行 / 角色） | 问题 5 + 问题 6 |
| 「未授权拦截」前端逻辑 | 路径决定 web-view / wx.login 起跳 URL |
| 操作日志「操作人」字段口径 | 问题 5 |

## 5. 风险提示

- 若 OQ 3.7 长期悬而未决，建议先按路径 C（独立小程序）做接口实现，因其依赖最少。一旦定为 A/B，桥接层重写、业务层不动。
- 若员工 App 团队的容器协议版本不固定（路径 A 风险），需在《纪要》中明确兼容版本与回滚策略，否则容器升级会带链上故障。
